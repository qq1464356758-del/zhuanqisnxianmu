# Third Pass Audit — Skill Farm 自我否决与收敛

## 纠正一：不要做 30 个碎片技能

原因：

- 用户技能安装位有限；
- 付费技能需要明确专业价值；
- 太简单的技能容易被平台原生能力或 Prompt 替代；
- 太多碎片技能会增加审核、维护、评价和售后表面积。

因此从「大量微技能」调整为「3~8 个高密度技能包」。

## 新主产品：ChinaOps — 中国业务确定性规则层

### 核心定位

给 AI Agent 一个不会靠猜的中国业务数据/日期基础层。

### 子能力

1. 工作日 / 法定节假日 / 调休补班 / N工作日截止日期；
2. 中国行政区划标准化、代码校验、新旧名称映射；
3. 业务标识符结构校验（仅格式/校验码，不查询个人数据）；
4. 中文金额、日期、数字、单位的确定性规范化；
5. 批量记录数据质量检查；
6. 严格 JSON 输出与错误报告；
7. 每次输出 data_version / rule_version，方便审计。

### 为什么比 DateOps 单品更好

- 一个安装位获得一组相关能力；
- 付费价值更容易解释；
- 专业性与数据资产更明显；
- HR、行政、CRM、采购、运营等 Agent 都能使用；
- 仍然不需要服务器或外部收费 API；
- 可用同一套自动测试框架维护。

## 第二候选：RAG Guard

目标：知识进入 AI 前先做机器化质检。

- 文档指纹与近重复；
- 老版本/重复版本识别；
- Chunk长度/标题/断句质量；
- HTML/Markdown噪声清理；
- 提示注入风险标记；
- PII 风险提示；
- 导入前报告。

风险：安全能力不能夸大为绝对防护；需避免给用户错误安全感。

## 第三候选：CRM Import Doctor

把上传的 CSV / Excel 在导入 CRM 前自动处理：

- 字段推断；
- 格式异常；
- 重复候选；
- 地址/日期/金额规范化；
- clean.csv + rejected.csv + report.json。

风险：个人信息处理，需要明确最小化数据留存与权限。

## 第四候选：Agent Handoff Kit

为多 Agent 协作生成统一交接包：

- 目标；
- 已完成；
- 证据；
- 未完成；
- 阻塞；
- 文件/产物；
- 风险；
- 下一 Agent 输入。

价值在于降低上下文漂移，但平台未来可能原生补齐，因此需要密切监控。

## 赚钱结构

真正想要的是：

`一次构建 → 平台商店自然发现 → 月度订阅 → 用户侧承担主要扣子资源消耗 → 官方数据变化时AI自动维护 → 人只终审`

这仍然不是“被动收入保证”。最关键验证点只有两个：

1. 付费审核能否通过；
2. 商店自然曝光能否产生真实订阅。

如果没有自然订阅，不做站外引流硬救，直接砍掉或换技能。

## 研究母公式

优先寻找：

**LLM容易错 + 官方/权威数据可更新 + 算法可确定 + 高频工作流需要 + 平台原生没覆盖 + 无外部成本。**

这是目前最稳定的“自动赚钱候选生成器”。

# Coze Skill Farm — 2026-09-14

## 结论

当前最符合「AI × 自动化 × 脚本 × AI员工 × 自动赚钱」的候选，不是人工任务，也不是传统SaaS，而是：

**付费 AI 技能微资产组合。**

结构：

`AI发现需求 → AI生成技能 → 自动测试 → 人工最终审核 → 上架技能商店 → 平台负责发现/购买/订阅/结算 → AI监控反馈与版本变化 → 自动维护`

## 为什么这条结构现在值得优先研究

截至 2026-09-14：

- 扣子付费技能服务协议于 2026-09-03 生效，仍处于非常早期阶段；
- 自然人可以作为技能创作者；
- 技能商店公开面向扣子用户；
- 个人版可申请商户入驻；
- 收款渠道支持支付宝、抖音支付；
- 付费技能按月购买/续费；
- 技能可以是 API 插件、自定义代码片段、数据检索工具等；
- 扣子 AI 本身可以根据自然语言描述与资料生成技能文件包；
- 商店用户使用扣子资源时，通常由实际使用者承担扣子资源消耗；如果我们不调用自己的外部付费 API，边际运行成本可以非常低。

这意味着存在一种经济结构：

**一次构建 + 月度订阅 + 平台流量 + 用户承担多数运行资源成本。**

这不是收益保证，只是当前研究中最符合自动化约束的结构。

## 硬淘汰规则

任何技能满足下列任一条件，直接砍：

1. 一句 Prompt 就能稳定完成；
2. 扣子原生已经提供同等能力；
3. 每个用户都要人工配置；
4. 我们每次调用都要支付明显外部 API 成本；
5. 售后无法标准化；
6. 功能依赖不稳定第三方页面；
7. 涉及高风险隐私、金融、医疗、法律决策；
8. 只是简单 API 套壳；
9. 无法写出自动回归测试；
10. 没有持续/月度使用理由。

## 第一轮候选

### S 级：China DateOps — 中国工作日 / 调休 / 截止日引擎

不是普通日历。

能力：

- 判断某日是工作日 / 周末 / 法定节假日 / 调休补班；
- N 个工作日前后日期；
- 两日期之间工作日数量；
- 自然语言期限解析，例如「三个工作日后」；
- 支持包含/不包含起始日两种口径；
- 批量日期计算；
- 返回计算路径与数据版本，减少 AI 幻觉；
- 年度节假日通知发布后自动更新规则文件并跑回归测试。

为什么值得做：

- 中国存在周末补班，通用模型容易按「周一到周五」误算；
- 官方每年发布明确节假日安排，数据源稳定；
- 无需服务器与外部付费 API；
- 可完全代码化、测试化；
- HR、采购、合同、SLA、运营 Agent 都可能使用。

风险：功能本身较窄，需通过「期限引擎 + 批量处理 + 可审计计算结果」提高专业性，避免被审核认为价值不足。

### S 级：China RegionOps — 中国行政区划标准化 / 历史迁移

能力：

- 省/市/区县名称标准化；
- 行政区划代码校验；
- 别名/简称匹配；
- 已撤销/更名地区映射到当前地区；
- 给定区县补全上级省市；
- code/name 一致性检查；
- 版本差异报告。

价值来自「版本化数据 + 映射关系」，不是 Prompt。

### A+：CRM Import Doctor — CRM / 表格导入前数据体检

输入 Excel/CSV，输出：

- 字段类型推断；
- 缺失值统计；
- 重复客户候选；
- 电话/邮箱/日期/金额格式异常；
- 中国行政区划纠错；
- 清洗后文件；
- 错误行文件；
- 结构化体检报告。

风险：客户文件可能包含个人信息，因此首版必须最小化数据保存与外部传输。

### A：Knowledge Deduper — AI知识库近重复清理

在文档进入 RAG 前：

- 内容指纹；
- 精确重复；
- 近重复聚类；
- 标题重复；
- 版本旧文档识别；
- 推荐保留版本；
- 清理报告。

### A：China Data Gate — 中文业务数据质量闸门

组合字段验证、规范化、去重和严格输出，用于 Agent → CRM / 数据库 / 表单写入前的最后一道门。

## 已经主动淘汰的伪机会

- 纯 JSON 校验：扣子已有 JSON / Code 评估器与结构化能力；
- 普通工具参数校验：平台自身存在请求参数强校验；
- 通用网页正文提取：平台和现有工具替代太多；
- Prompt模板：太容易复制，同质化严重；
- 普通总结/改写/表格分析：通用 Agent 已能完成；
- 单 API 包装：付费技能审核规则明确不欢迎无附加价值的 API 套壳。

## AI 员工编制

### Scout

每天只生成候选，不写产品。

目标：发现「模型容易出错，但代码/数据可以给确定答案」的问题。

### Native Auditor

先检查扣子原生能力，如果原生已覆盖 70% 以上，直接否决。

### Value Auditor

必须回答：为什么用户愿意连续第二个月续费？

### Builder

把通过审核的候选转换为技能包、脚本、测试数据、README、示例。

### QA

至少生成：

- 正常案例；
- 边界案例；
- 错误输入；
- 大批量输入；
- 历史版本回归案例。

没有可自动测试的技能，不上架。

### Publisher

生成技能名称、封面文案、Before/After、精选案例、价格建议。

### Maintainer

监听官方规则和平台变更，只有发生变化才触发维护。

### CFO

每月只看：

- 订阅数；
- 续费率；
- 售后次数；
- 维护分钟数；
- 净收益。

30 天没有真实购买且自然曝光足够，降级；维护成本超过收入，删除。

## 核心目标

不是打造一个爆款。

目标是：

**10~30 个边际运行成本接近 0 的小技能，其中少数形成稳定月订阅。**

这更像互联网里的「自动售货机组合」，而不是创业公司。

## 当前第一实验

优先验证 `China DateOps`，不是因为预计收入最高，而是因为：

- 构建最简单；
- 数据可获得；
- 最容易自动测试；
- 零外部 API；
- 零真机；
- 零客户配置；
- 可以快速验证付费技能的完整上架/结算链路。

如果技能审核或自然购买完全不成立，则整个 Skill Farm 路线迅速降级，不继续沉没成本。

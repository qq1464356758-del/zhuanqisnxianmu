# Hierarchy Alpha：不抢大厅，研究平台内部的小队列

## 核心假设

公开任务大厅不是机会本身。真正值得研究的是：

`公开任务 → 认证任务 → 等级权益 → 专属任务 → 精英优先 → 团队分配 → 审核/终审/改错 → 管理/质量控制`

每往右一步，通常意味着：

- 用户更少；
- 平台筛选更严格；
- 质量要求更高；
- 任务可能更稳定或更优先；
- 普通“副业教程”更少讨论。

这符合单人容量套利：大需求在底层，边缘收益在小队列。

## 已发现的真实结构

### 百度众测

公开帮助页显示：

- 高难度标注项目可要求练习、考试、认证；
- 精英计划有高奖励项目优先答题权；
- 公会可获得专属高礼券题目和津贴；
- 团队任务只有被分配到的公会才能领取；
- 会长可审核、修改成员答案，优秀审核可能有额外奖励；
- 考试测评页面存在“标注项目 / 审核项目 / 终审项目 / 改错项目”分类；
- 历史测试军团规则存在按审核数量和准确率支付的审核员层。

注意：某些历史角色当前可能暂停招募，所以不能把旧规则直接当成今天可进入的岗位；要以账号内当前入口实测。

### 腾讯搜活帮

官方 App 当前仍以“众包任务换取可提现报酬”为定位。历史版本记录显示平台曾加入：

- 用户成长体系；
- 等级权益；
- 专属任务；
- 经验值；
- 公会。

这说明任务平台常见的真实设计不是“所有人看到同一批任务”，而是存在用户分层。

### Testin

- 任务按贡献和等级计算收益；
- 最近任务表现形成铜/银/金/钻等级，不同等级有报酬加成；
- 用例任务可由专家团队分配；
- 公开任务大厅存在人数上限和短时间任务。

### 京东众智

当前官网仍提供数据标注服务；公开协议定义个人、团队、公司都可作为用户领取任务，并按完成情况获得奖励。

## 我们真正要测的不是“哪个平台赚钱”

需要记录一个账户从第 0 层升级到第 N 层的路径：

| 字段 | 记录内容 |
|---|---|
| unlock | 解锁条件：考试/等级/正确率/任务数 |
| queue | 解锁后出现的新任务类型 |
| frequency | 每周出现次数 |
| pay | 单任务实际到账 |
| minutes | 实际耗时 |
| rejection | 被拒/无奖励比例 |
| competition | 名额与填满速度 |
| hidden_bonus | 等级、津贴、优先权等附加收益 |

核心指标：

`有效时薪 = 实际到账 × (1 - 拒绝率) / 实际耗时`

`层级价值 = 解锁后有效时薪 - 解锁前有效时薪`

如果某个认证花 3 小时，却让之后一个月的有效时薪从 12 元提高到 35 元，那么真正的“财路”不是任务，而是那 3 小时认证。

## 单人策略

1. 不追求拉人建大公会。
2. 不多账号、不脚本答题、不绕规则。
3. 只优化自己的等级、认证、正确率和任务选择。
4. 用雷达减少“没看到任务”的损失。
5. 找到一个小队列后不公开扩张，只验证它是否能稳定覆盖个人目标。

## 目前判断

这是当前研究中最接近“低级图稳定掉落”的线上合法结构：

**平台有海量真实需求 → 普通层很拥挤 → 质量体系把用户分层 → 小部分任务被分配给更高层 → 一个人不需要改变整个市场。**

下一步不是继续看宣传，而是实际注册账户后记录 14~30 天的任务、解锁和到账数据。
